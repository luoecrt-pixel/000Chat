## 2. Размер/формат ошибок без молчаливого сжатия

OpenRouter images не сжимаются и не downscale-ятся.

Для обычного изображения отправляются исходные байты локальной копии.

Для JPEG/PNG/WebP/GIF с EXIF orientation != normal создаётся один дополнительный wire-artifact в PNG:
- пиксели ориентируются по EXIF;
- PNG является lossless encoding;
- исходная local copy сохраняется отдельно;
- следующие раунды используют тот же wire-artifact;
- новый JPEG compression не выполняется.

Android ExifInterface документирует EXIF orientation и rotation semantics:
https://developer.android.com/reference/androidx/exifinterface/media/ExifInterface

Если коррекция EXIF не может быть выполнена из-за слишком большого разрешения или нехватки памяти, файл отклоняется явной ошибкой, а не отправляется в потенциально неправильной ориентации.

Если OpenRouter/provider возвращает ошибку запроса, UI теперь дописывает размеры вложений:
- исходный размер;
- размер wire-artifact, если он отличается.

Таким образом HTTP 400/413 или provider-specific size/format rejection больше не выглядит как ошибка без информации о файле.

OpenRouter документирует image_url, base64 data и отдельные image blocks для нескольких изображений:
https://openrouter.ai/docs/guides/overview/multimodal/image-understanding

## 3. ZIP-slip и большие тексты

Добавлена центральная проверка isUnsafeZipPath().

Отклоняются entry paths:
- начинающиеся с /;
- содержащие компонент ..;
- содержащие Windows drive prefix вроде C:/.

Небезопасная запись не используется как filesystem path: entry только дочитывается до конца в рамках существующих zip limits и сообщается как skipped.

Сохранились ограничения:
- максимум 100 entries;
- максимум 25 MB на entry;
- максимум 200 MB распакованного суммарного размера.

Nested zip/apk/jar автоматически не распаковываются.

Текстовые файлы не режутся по размеру в attachment layer:
- содержимое читается целиком;
- UTF-8 strict;
- fallback windows-1251;
- NUL byte => binary;
- decoded text один раз сохраняется как UTF-8 artifact;
- следующий раунд использует тот же text artifact.

Добавлен тест на большой текст, проверяющий полное совпадение исходного и отправляемого decoded content.

## 4. /api/v1/models cache

Preflight model capabilities теперь:
- хранит успешный результат в process-local cache по model id;
- не делает новый /api/v1/models request на каждую отправку;
- имеет короткий 2-минутный retry backoff после failed request или отсутствующей model record;
- если endpoint недоступен, preflight не блокирует отправку;
- если capability явно известна и несовместима, запрос блокируется с понятной ошибкой до отправки.

Для image проверяется input modality image.
Для PDF проверяется file.

## 5. EXIF portrait

Для images с EXIF orientation != normal:
1. читается orientation;
2. декодируются исходные pixels;
3. применяется соответствующее rotate/flip;
4. создаётся один lossless PNG wire-artifact;
5. именно этот artifact отправляется через image_url data URL.

Исходный JPEG остаётся в private storage и не заменяется.

Это намеренно отличается от resize/compression: цель — устранить неоднозначность EXIF orientation, не жертвуя деталями JPEG через повторный JPEG encode.

Важно: текущий connector не даёт физически выполнить реальный запрос к выбранной модели/устройству из этого PR. Поэтому факт «конкретный provider/model визуально правильно прочитал именно тестовое EXIF-фото» здесь не объявляется как runtime-proven; код гарантирует корректно ориентированный wire-artifact при наличии EXIF и покрывает саму ветку unit/source-level проверками.

## 6. ZIP теперь копируется сразу

Для OpenRouter ZIP больше не остаётся зависеть от исходного content:// до отправки:
- сначала создаётся private local copy;
- затем local copy распаковывается;
- исходный временный ZIP удаляется после успешного preparation;
- в history остаются подготовленные files.

Старый pending ZIP recovery path тоже сохраняется для уже существующих composer states.

## 7. GitHub tools / local files

Без github_tools:
- GitHub tools не попадают в catalog;
- repo/branches system context отсутствует;
- GitHub tool_trace не записывается.

При этом отдельный app tool create_local_text_file остаётся доступен: это не GitHub tool.

Добавлен реальный локальный file creation path:
- UTF-8 text/code artifact в filesDir/generated;
- artifact metadata сохраняется в assistant message annotations;
- существующий экран «Локальные файлы Astra» даёт просмотр/сохранение/поделиться/удаление.

GitHub create_or_update_file confirmation показывает repository, branch, path, размер и preview.

## 8. History / prompt cache

Attachment manifest хранит:
- id;
- name;
- kind;
- path;
- mime;
- original size;
- SHA-256;
- text path/encoding;
- wire path/mime при EXIF normalization.

Base64 в SQLite не хранится.

Второй запрос использует тот же local artifact и тот же wire-artifact, поэтому attachment prefix не пересоздаётся заново.

## 10. Actions

Автоматические triggers остаются отключёнными в обоих workflow:
- build.yml: workflow_dispatch only;
- release.yml: workflow_dispatch only.

Проверка commit status текущего PR head через GitHub connector вернула пустой список statuses.
fetch_commit_workflow_runs также вернул пустой список.

Причина: доступный connector предоставляет чтение workflow runs и rerun уже существующих jobs, но отдельной операции workflow_dispatch в текущем наборе инструментов нет. Поэтому Debug и Release вручную из этого сеанса запустить нельзя без нарушения условия «не включать auto-trigger».

PR #57 поэтому намеренно НЕ мержится до ручного запуска:
- Debug — один раз;
- Release — один раз;
и проверки, что оба workflow полностью success.
