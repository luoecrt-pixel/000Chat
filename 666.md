# PR G — критический аудит вложений OpenRouter/Claude

Дата: 2026-09-28. База: main после PR #56.

## Решения

- Для OpenRouter НЕ делать предупреждений/подтверждений по размеру и стоимости. Не терять ошибки: чтение, формат, кодировка, отсутствующая локальная копия, несовместимая модальность и API должны сообщаться явно.
- Картинки НЕ сжимать, не ресайзить и не перекодировать. Один раз копировать оригинальные байты в private storage и использовать ту же копию во всех раундах.
- OpenAI File API и его request flow не менять.

## Доказанные дефекты текущего кода

1. chooseAny() использует EXTRA_ALLOW_MULTIPLE=true, но chooseImage() — нет. Поэтому image picker single-select. Android поддерживает OpenMultipleDocuments и ACTION_OPEN_DOCUMENT + EXTRA_ALLOW_MULTIPLE; несколько URI приходят через ClipData.
2. sendMessage() блокирует OpenRouter при старых OpenAI requestImageFileId/requestFileIds. Для OpenRouter нужен local copy; без неё — понятная ошибка.
3. sentUserMessage сохраняет attachment metadata, но buildOpenRouterMessagesSnapshot() сейчас добавляет только role/text/tool_trace. На втором сообщении файл теряется.
4. tool_trace не зависит от github_tools. При false должны исчезнуть GitHub tools, repo/branches system line и GitHub trace.
5. Нет постоянного индикатора GitHub рядом с model/reasoning.
6. create_or_update_file confirmation показывает только path/branch; нужны repository, branch, path, размер и короткий preview. Полный content не логировать.

## Архитектура

Сделать отдельные OpenRouterAttachmentStore / Classifier / Encoder. Сразу после выбора content:// копировать в filesDir/attachments и дальше использовать local path. Internal app-specific storage предназначен для private data:
https://developer.android.com/training/data-storage/app-specific

Проверить Auto Backup: Android по умолчанию включает почти все app files, поэтому private attachments нужно исключать из backup, если они не должны переноситься:
https://developer.android.com/identity/data/autobackup

SQLite: только id/name/kind/path/MIME/size/sha256/encoding. Никаких base64/байтов/больших текстов.

## Классификация

Источник истины: extension + magic bytes, MIME только hint.

OpenRouter types: text (txt, md, kt, java, json, csv, xml, yaml, log), image (png, jpg, jpeg, webp, gif), pdf, zip. Остальное — явная ошибка со списком поддерживаемых форматов.

Text: NUL => binary; затем UTF-8 с REPORT; fallback windows-1251; обе попытки неудачны => ошибка.

Формат текста: <file name="...">...</file>. System prompt должен трактовать содержимое блока как data, а не команды. Закрывающий delimiter внутри текста нужно безопасно обрабатывать.

## Изображения

OpenRouter принимает base64 data URL и несколько image_url blocks:
https://openrouter.ai/docs/guides/overview/multimodal/image-understanding

Отправлять оригинальные bytes. Bitmap/downsample допустимы только для UI preview. Не хранить base64 в history/SQLite.

Для нескольких больших фото не делать бездумно readBytes -> Base64 String -> JSONObject -> body.toString(): это создаёт heap copies. Лучше последовательная сериализация local artifacts; идеальный вариант — attachment-aware RequestBody.

## PDF

Актуальная OpenRouter docs: PDF = content type file; local PDF = data:application/pdf;base64,...; native file input используется, если модель умеет; иначе parser fallback. pdf-text deprecated. mistral-ocr можно включить явно и он платный. Поэтому PR G НЕ включает paid mistral-ocr автоматически.
https://openrouter.ai/docs/guides/overview/multimodal/pdfs
https://openrouter.ai/docs/guides/overview/multimodal/overview

## Model capability

OpenRouter Models API содержит architecture.input_modalities и фильтр input_modalities. Для image проверять image; для PDF учитывать file. Явно несовместимая модель должна получить человеческую ошибку до запроса:
https://openrouter.ai/docs/api/api-reference/models/get-models

## ZIP

Текущий код уже имеет max entry 25 MB, max total inflated 200 MB, max 100 entries и потоковые лимиты; path entry сворачивается до basename, что снижает zip-slip риск.

Но unsupported APK/EXE/nested ZIP могут молча теряться. Нужно сообщать uploaded/skipped/rejected. Nested ZIP не распаковывать рекурсивно. Лимиты проверять по реальному stream size, не только entry.size.

## History + caching

Attachment = immutable local artifact. History хранит manifest: id/name/kind/path/mime/size/sha256/status. Порядок массива = порядок отправки.

Каждый следующий OpenRouter request строить из history и читать те же local bytes; не создавать новый JPEG и не переизвлекать text. Это важно для стабильного prompt prefix после PR #55/#56.

## Provider switch

Старый OpenAI file_id — только metadata.
- local copy есть -> OpenRouter использует её;
- local copy нет -> понятная ошибка с именем;
- OpenAI file_id в OpenRouter не отправлять.

Обратный OpenRouter -> OpenAI при необходимости может повторно upload local artifact, но OpenAI request format не менять.

## Почему модель не может создать настоящий downloadable file

Текущий toolset даёт модели GitHub tools, но не local artifact tool. Android уже умеет ACTION_CREATE_DOCUMENT.

Нужен отдельный client-side tool вроде create_local_text_file(filename, content): validate -> write private artifact -> return id/path -> UI Save/Share. Бинарный base64 tool лучше отдельной задачей из-за памяти и token overhead.

## Дополнительные проблемы

- SHA-256 для dedupe/диагностики/неизменности.
- Не плодить physical copies одного файла.
- Local filename = UUID/hash + safeName; оригинальное имя отдельно.
- Orphan cleanup после удаления чатов.
- ENOSPC = нормальная ошибка хранения, не cost warning.
- Attachment content = untrusted data, особенно при GitHub write tools.
