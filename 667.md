## Что реализовано

### OpenRouter attachments
- OpenRouter больше не использует OpenAI Files API для пользовательских вложений.
- После выбора файл копируется в private app storage: filesDir/attachments.
- Источник content:// больше не нужен после копирования.
- Для OpenRouter введён локальный attachment store с metadata:
  id, name, kind, path, mime, size, sha256, text_path, text_encoding.
- Base64 не хранится в SQLite.

### Классификация
- MIME больше не является единственным источником.
- Учитываются extension и magic bytes.
- text: txt/md/kt/java/json/csv/xml/yaml/yml/log.
- image: png/jpg/jpeg/webp/gif.
- pdf и zip.
- unsupported формат даёт явную ошибку.
- NUL byte делает text-файл бинарным.
- text decoding: strict UTF-8, затем windows-1251.
- Текст сохраняется один раз как UTF-8 derived artifact.

### Изображения
- Сжатия/resize/re-encode нет.
- Network payload использует оригинальные байты local copy.
- Несколько изображений передаются в одном OpenRouter content array.
- Кнопка image picker теперь имеет EXTRA_ALLOW_MULTIPLE=true.

### PDF
- Передача через OpenRouter file content с data:application/pdf;base64 URL.
- Платный mistral-ocr принудительно не включён.
- Перед отправкой проверяется input modality выбранной модели через /api/v1/models.
- Image -> требуется image modality.
- PDF -> требуется file modality.
- При явной несовместимости запрос не отправляется.

### History
- User message теперь может хранить attachment manifest.
- buildOpenRouterMessagesSnapshot() восстанавливает attachments из history.
- Старые сообщения с OpenAI file_paths/image_path также мигрируются в local manifest.
- После migration manifest записывается в сообщение, чтобы derived text не создавался заново.
- Порядок attachments стабилен.
- Второе сообщение в том же чате снова содержит исходные attachments.
- Edit/regenerate восстанавливает OpenRouter attachments.

### Prompt caching
- Один и тот же local artifact используется в последующих раундах.
- Картинки не пересжимаются.
- Text derived artifact не пересоздаётся после migration.
- Это сохраняет стабильный prefix лучше, чем генерация нового payload на каждый раунд.

### ZIP
- Для OpenRouter ZIP распаковывается локально.
- Сохраняются лимиты: 100 entries, 25 MB на entry, 200 MB total inflated.
- Лимиты считаются по фактическому stream.
- Nested zip/apk/jar не распаковываются рекурсивно.
- Unsupported entries теперь сообщаются через diagnostics/status вместо молчаливого исчезновения.
- Existing OpenAI ZIP path оставлен отдельно.

### GitHub tools
При github_tools=false:
- GitHub tools не добавляются в tool catalog;
- system line про repository/branches отсутствует;
- GitHub tool_trace не сохраняется и не подмешивается в history.

При github_tools=true:
- существующий GitHub toolset остаётся;
- repository/branches system context сохраняется;
- trace сохраняется.

Добавлен видимый indicator GitHub ✓ / GitHub выключен рядом с reasoning badge.

### GitHub write confirmation
create_or_update_file confirmation теперь показывает:
- repository;
- branch;
- path;
- размер;
- preview первых 3000 символов;
- отметку об обрезанном preview.

Audit sanitization полного content не менялась.

### Реальные локальные файлы от модели
Добавлен client-side tool:
create_local_text_file(filename, content)

Он:
- создаёт настоящий UTF-8 файл в filesDir/generated;
- возвращает path/filename/mime/size;
- сохраняет artifact в assistant annotations;
- существующий экран «Локальные файлы Astra» автоматически видит такие файлы и даёт Просмотр/Сохранить/Поделиться/Удалить.

Это устраняет ситуацию, когда модель говорит, что настоящие файлы создать нельзя.

### Cleanup
- Добавлен сбор ссылок на local files из всех чатов.
- Старые orphan attachments в filesDir/attachments удаляются после 7 дней, если на них нет ссылок и они не находятся в текущем composer state.
- AndroidManifest уже имеет allowBackup=false, поэтому отдельные backup rules для private attachments не потребовались.
