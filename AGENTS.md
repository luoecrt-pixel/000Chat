# AGENTS.md — правила работы с репозиторием

**Главный источник истины — `NEXT_AGENT_HANDOFF.md` из актуального `main`. Не заменять его документами пакета.**

Инструкции владельца в текущем разговоре приоритетны. Этот архив — частичный cumulative patch, не полный проект. Дополнительные материалы пакета: `BUNDLE_AGENT_HANDOFF.md` (краткий актуальный статус), `AGENT_IMPLEMENTATION_RULES.md` (ограничения и контракты), `RENDERER_DISTRIBUTIONS.md` (правила SHA для KaTeX/Mermaid). Большие устаревшие REVIEW/AUDIT/CHECKPOINT заметки намеренно не включены.

**Репозиторий**: `luoecrt-pixel/000Chat`, переименован из `luoecrt-pixel/OpenAIApiChat`. **База patch**: `4111b83a215da03af544e8c0477246962c43395b`; актуальный `main` уже ушёл вперёд. Сверяй HEAD, незакоммиченную работу и PR; не переписывай чужие изменения и не применяй патч вслепую. `START_HERE.md` лежит в корне ZIP, а не в репозитории.

**Приоритет**: получить полный checkout, проверить конфликтующие изменения, скомпилировать Debug и unit tests, воспроизвести реальные ошибки, исправить причины. Внесённые тесты не считать выполненными только потому, что они написаны. Результаты статического Python verifier, локальных host-проб и Android test suite указывать раздельно.

**Не нарушать контракты**: Stop, request-aware SQLite CAS, полная история сообщений, локальные оригиналы вложений, lossless файлы/фото, signed Claude replay, ручной reasoning effort, fingerprint v1, 1h cache, аварийная граница 5 ч/5 млн токенов на один ответ и его tool rounds. Не вводить скрытые лимиты output/tokens, фиксированные tool-раунды, idle timeout или тихое усечение контекста. Не ослаблять SHA-проверки ресурсов, TLS, Android Image/JPEG validation и защиту от неверного владельца запроса ради зелёных тестов.

**Не менять README**, не выполнять платные API-запросы, не работать с телефоном без отдельного поручения. Релизные Actions запускать по CI/merge-правилам канонического handoff через branch [ci]; workflows и настройки публичности без отдельной задачи не менять. Последнее ограничение текущего этапа владельца — 40 минут; перед остановкой сохранять фактическое состояние кода и невыполненные проверки в новом кратком checkpoint, без накопления десятков исторических сообщений.
