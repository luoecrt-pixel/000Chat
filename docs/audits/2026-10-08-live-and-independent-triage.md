## 1. Что пользователь действительно показал на Android

1. **OpenRouter/Claude, реальная ошибка (live negative proof).** На экране получена ошибка:
   `cachecontrol: a ttl='1h' cachecontrol block must not come after a ttl='5m' cachecontrol block. Note that blocks are processed in the following order: tools, system, messages.`
   Source-level причина видна непосредственно: `OpenRouterChatClient.requestMessage()` добавляет top-level `cache_control={type:ephemeral,ttl:1h}` для `anthropic/*`, а `MainActivity.buildOpenRouterMessagesSnapshot()` добавляет explicit `cache_control={type:ephemeral}` к `system.content`, что означает default **5 минут**. Automatic marker может оказаться после explicit 5m в растущей истории, нарушив TTL-порядок. Официальные правила: https://platform.claude.com/docs/en/build-with-claude/prompt-caching и https://openrouter.ai/docs/guides/best-practices/prompt-caching. **P0 — чинить прежде остальных UI-улучшений**; regression должен моделировать всё `tools → system → messages` и несколько раундов инструментов, а не изолированный системный блок. Кандидат — убрать лишнее пересечение automatic/explicit breakpoints либо согласовать длительность и порядок всех фактических блоков; сохранить provider compatibility и проверить cache usage, не просто подавлять ошибку.
2. **Потеря экранного пространства (device UI).** Строка заголовка и карточка событий занимают непропорционально много высоты; раскрытая история не имеет явной кнопки «Закрыть». Снизу `📎`/`🖼` визуально слиты; модельный badge и надпись про GitHub нагружают composer; кнопка effort слишком близко к вложениям. Есть реальный скриншот с корректно поднятым composer над IME, но он не доказывает всех сценариев insets/rotate. Образец компоновки пользователя — минималистичный мобильный composer как на приложенном экране Claude, **без буквального копирования чужого фирменного оформления**.
3. **Stop и неполная стоимость (live observation).** В истории после Stop показано `0 in · 0 out · $0.0000`; в Diagnostics есть `response_created`, `request_cancelled`, `background_response_cancel status=200` для одного OpenAI запроса. `MainActivity.stopCurrentResponse()` возвращает исходный ввод и инициирует отмену Responses; при отмене `recordRequestEvent` не располагает финальным usage, `RequestEventFormatter` печатает нули, а БД по умолчанию записывает zero. **Ноль в UI = нет переданной статистики, НЕ доказательство бесплатности.** Сумма могла начислиться за уже обработанные токены; верифицировать только по provider usage/billing dashboard / response usage, если доступен. План: статусы «Отменено; данные о расходе пока недоступны», отдельно провайдера/фактическую модель; при доступности usage — обновить корректно, без ложного $0. При Stop возможна стоимость даже когда поле ввода восстановлено.
4. **Пузырь «Astra» и `response=unknown`.** Отправка из ChatGPT/OpenAI и Claude/OpenRouter в одном чате показана пользователем; ответ «Я — ChatGPT» в ранней реплике не доказывает, кто отвечал после переключения провайдера. `requested_model` фиксируется, `response_model` для failed/cancelled остается unknown. Требуется сохранять **провайдера/модель на уровне каждого сообщения**, а не переименовывать задним числом при изменении текущих настроек.

Скриншоты — внешние пользовательские наблюдения без криптографической привязки к hash установленного APK. Логи показывают `version=4.17.0`, но версия одинакова между несколькими PR: не приписывать всё конкретному APK без сравнения сборки.

## 3. Порядок реализации (мелкие PR, доказательства раньше изменений)

1. **PR A: local file ownership / cleanup**. Покрыть collection из messages **и всех черновиков**, включая `wire_path`/`text_path`/`path`. Сначала воспроизвести негативный тест с возрастом >7 суток, затем исправить. Не трогать удаление внешних URI; сохранять ограничение `filesDir/cacheDir`.
2. **PR B: attachment fingerprint + SQLite сохранение.** Тест, что обновление только `attachments` вызывает SQL UPDATE, и `wire_path` переживает reopen.
3. **PR C: OpenRouter caching failure, подтверждённый телефоном.** Фикс невалидной комбинации 1h/5m в реальном сформированном HTTP body с `tools+system+messages`, multi-round, testing supported providers. После Build/Release провести повторный настоящий Claude запрос и убедиться, что ответ и usage получены.
4. **PR D: message metadata persistence.** DB schema migration, сохранение `tool_trace`, `reasoning_summary`, `response_model`, `provider`/requested model и `error`; тест read/write/migration/reopen и поведение соседних запросов/удаления. Оценить, какие метаданные хранить только в `request_events`, прежде чем дублировать.
5. **PR E: GitHub write safety.** Confirmation previews, обязательный/проверенный read ref, CI/head eligibility на merge, проверка тестами и GitHub approval dialog. Branch protection отдельно зависит от возможностей GitHub аккаунта и действий пользователя.
6. Затем triage recovery deadline, OpenRouter preflight ownership, memory stress; регулярный реальный provider/device прогон. Дизайн UI не блокирует исправления потери данных.

Для каждого **code PR**: реальный red/green regression на релевантном harness, финальные `push Build Android APK` и `push Build Android Release` — **Successful** на code head; Verify handoff — Successful если редактировался handoff. Не выдавать skipped PR-build за green.

## 4. Отложенный UI-план по обратной связи пользователя

- **Заголовок/события.** Вместо высокой статусной строки и всегда видимой большой карточки — компактная цветная кнопка-индикатор состояния запроса (успех/ошибка/отмена/incomplete/unknown); раскрываемая история с явной кнопкой закрытия. Ошибка доступна без потери деталей; цвет не единственный канал (текст/иконка).
- **Нижний composer.** Визуально разделить `📎` и `🖼` нормальными отступами/минимальным touch target. Убрать из главного ряда badge модели/источника и текст «GitHub выключен», но не удалять соответствующие настройки/безопасность инструментов. Поместить настройку reasoning effort в компактную область **под сообщениями и рядом с composer** по референсу пользователя, а не между кнопками вложений. Сохранить Send/Stop, mic и IME/insets.
- **Настройки усилия.** Удалить дублирующий reasoning-effort picker из Settings после переноса на главный экран. В одном popover также показывать `standard/pro` **только если реально поддерживаются выбранной парой API source + model**. Текущее `reasoning_mode=standard/pro` — часть специфического OpenAI request builder (использует `reasoning.mode` и `configuration_update`), в OpenRouter такой UI сейчас не отправляется; нельзя рисовать универсальный toggle. Отдельно контролировать `temperature` («градус», randomness) и `reasoning effort` (глубина мышления): это разные настройки.
- **Подписи ответов.** В пузыре вместо неизменного «Astra» показывать grounded label **реальной или запрошенной** модели и source, различая известную `response_model`, запрошенную модель и unknown. Сначала P1 сохранение message metadata, чтобы старая история не переименовывалась задним числом при смене модели.
- **Стоимость/статусы.** При cancelled/failed без usage показывать «неизвестно», а не гарантированный ноль, и разрешить посмотреть причину ошибки/предыдущее событие. Не смешивать ошибку OpenRouter с низкой стоимостью.
- **UI proof:** device smoke на узком/широком экране, клава/IME и rotate, 2–3 чата, expanded telemetry, big title, edit system prompt; проверка доступности кнопок и отсутствие случайных запросов при смене effort/model.

**Первый UI-шаг:** pure view-state contract для панели событий и capability-aware effort-selector + Android ActivityScenario layout smoke на маленькой высоте, не начинать с Compose rewrite.

## 5. Уточнения пользователя после независимого аудита

**Наблюдение о расходах:** пользователь сверил биллинг провайдера и сообщил списание **$0.20** после экспериментов с остановкой запросов. Это пользовательское подтверждение суммарных расходов, **не** точная стоимость какого-либо конкретного `request_id`, пока нет привязки через API/billing. Задача — по возможности показать фактическую сумму в приложении, включая отменённые запросы. Первый шаг: проверить, возвращает ли `GET /responses/{response_id}` usage после `cancel` и/или доступен ли провайдерский generation-lookup, безопасно связать факт расхода с `request_id`; обновлять request event из подтверждённого источника. Если API не отдаёт usage для отмены — показывать `Расход ещё неизвестен` / ссылку на расход в аккаунте, **не** выдумывать ноль или цену по несуществующим токенам. Предусмотреть повторный reconcile при следующем открытии, без бесконечных опросов и повторной оплаты запроса. Проверить сценарии `response_created` → Stop → успешный server cancel (HTTP 200) → спустя время доступный/недоступный usage.

**События и верхняя часть:** пользователь **не просит убирать строку событий**. Вернуть ей прежний компактный вид **без фоновой рамки/большой карточки**, оставить цвет и нажатие для раскрытия деталей. Добавить отдельную заметную кнопку «Закрыть» в раскрытом списке. Компактно пересобрать заголовок/status/safe padding и не занимать высоту чата пустыми блоками. На Android статус-бар и область жестов нужно соблюдать: сперва оптимизировать расположение внутри доступного пространства с `WindowInsets`; `FLAG_FULLSCREEN`/скрытие уведомлений считать **необязательным будущим режимом**, только после проверки на устройстве, доступности шторки, клавиатуры и навигационных жестов — не включать автоматически ради экономии нескольких пикселей.

**Drawer жестом:** пользователь хочет раскрытие **свайпом слева направо**, а закрытие справа налево. `DrawerLayout` уже установлен и в `MainActivity` нет явного `setDrawerLockMode`; AndroidX обычно поддерживает edge swipe по умолчанию. **Не считать feature отсутствующей без phone-proof.** Сначала протестировать из левого края при gesture navigation, при открытом чате и скролле, затем исправлять interception/edge sensitivity при реальном воспроизведении.

**Настройки:** сейчас один длинный перегруженный диалог. Product-план: компактные разделы «API и модель», «Мышление и ответ», «Инструменты», «Файлы», «Диагностика/дополнительно»; первое действие — переиспользовать уже существующие контролы, не менять request semantics. Часто используемые `effort` и (только при поддержке model/source) `standard/pro` — в небольшое меню у composer, а не дублировать в Settings; сложные JSON Schema/Vector Store/cache controls раскрывать только в Advanced. Tool toggles и чувствительные функции не прятать без объяснения. Реальный шаг — скетч IA (information architecture) и тест доступа ко всем текущим действиям без потери prefs/setting values; затем поэтапный UI, а не один rewrite `MainActivity`.

**README:** в обозримом плане **не трогать**. Пользователь не использует этот файл; он не является источником правды для агента. Теоретическая ценность для новых посетителей GitHub не оправдывает отвлечение от P0/P1. Сохранить как есть до отдельного решения; не запускать docs-only PR для уборки README.
