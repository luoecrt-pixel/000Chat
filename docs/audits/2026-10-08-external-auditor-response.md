## Новые независимые находки с телефона (аудитор не мог их знать)

1. **Живая ошибка Claude/OpenRouter по caching TTL**: `cachecontrol: a ttl='1h' ... after a ttl='5m'`. Source-level сочетание explicit 5m в system и top-level automatic 1h подтверждено; **PR #103 — в CI** удаляет 5m marker, оставляя одну автоматическую 1h политику, и добавляет tests с tools/system/многими раундами. До реального повторного запроса Claude не утверждать, что ошибка исчезла на телефоне.
2. **Расход после Stop:** пользователь проверил панель биллинга и сообщил **$0.20 списаний**, тогда как приложение показывало нули. Это пользовательское aggregate-наблюдение, не цена каждого отдельного request. Stop возвращает input; он **не отменяет факт уже обработанных платных токенов**. Нет финального usage → в UI нужно `неизвестно`, а не нулевая стоимость. Проверить endpoint OpenAI retrieve/cancel, OpenRouter `/generation?id=...` только при наличии реального generation ID, не моделировать цифры. UI/persistence reconciliation — открытая задача.
3. **UX замечания с экранов:** карточка событий слишком высокая. Пользователь уточнил: **оставить компактную цветную строку без рамки**, а не скрыть её; добавить явный «Закрыть» в expanded. Уменьшить высоту top content, но соблюдать status-bar/safe insets; full-screen лишь после отдельного phone UX доказательства. Drawer — открыть/закрыть свайпом, сначала проверить native AndroidX DrawerLayout (lock mode не установлен). Компоновка composer по референсу Claude, но без полного копирования; аккуратные отдельные 📎/🖼, убрать повторяющие model/GitHub badges, effort и при поддержке source/model standard/pro рядом с вводом. Модель конкретного сообщения после DB metadata preservation. Перегруженный Settings сгруппировать по задачам, редко используемые опции в Advanced. Всё это **спланировано**, UI не изменён.

## Почему порядок отличается от исходного аудита

- Риски необратимой потери пользовательского файла/манифеста и **живое** неправильное формирование запроса Claude выше, чем чистка README, Gradle Wrapper и косметика.
- Вместо нескольких несвязанных правок по файлам объединены однотипные правила сохранности `wire_path`, всех composer drafts и `attachments` fingerprint в **PR #101**, потому что они участвуют в одном контуре ownership/cleanup/persistence. Это не отказ от регрессионных тестов для каждого случая.
- UI и actual billing/cancelled usage **не игнорируются**, но не замещают P0 исправлений. Ограничения provider/model на `standard/pro` нельзя обходить универсальными переключателями.
- Критические замечания не превращены без тестов в готовые утверждения об Android: часть — доказанные source-level mismatches, часть — риски, один Claude-отказ — живой screen error, сумма $0.20 — сведения из аккаунта со слов владельца.
- Ответ для вас поддерживается в **этом файле**. Когда будут полностью закрыты все выбранные задачи (либо сознательно и окончательно отвергнуты), добавить финальную секцию «Завершено / намеренно не исправлено» с точными PR, CI run IDs и proof limits. До тех пор файл не обозначает завершение полного аудита.
